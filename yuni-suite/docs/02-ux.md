# 02: UX

## Who it's for
| Persona | Needs | Pain today |
|---------|-------|-----------|
| Student (year 1 to 5) | Know what's next, find rooms, study efficiently, hear campus news | Scattered WhatsApp groups, missed notices, flaky data |
| Student gov leader | Reach the right people, get responses, run polls | No targeting, no read receipts, forms scattered |
| Admin | Publish official info, moderate | Manual, repetitive uploads |

## Information architecture
```
Home      daily brief, next class, due soon, agent nudge
Study     flashcards, past papers, focus rooms, agent chat
Map       campus map, study spots, directions
Feed      announcements, polls, forms, events, sports, clubs
Me        profile, settings, SARIS button, sync status, safety
```
SARIS lives under **Me** and as a shortcut on Home. It opens in the in-app browser, nothing else.

## Key flows

### 1. Onboarding (under 60 seconds)
1. Welcome, pick language
2. Programme and year
3. Pick interests: sports, clubs
4. Notification permission, with a reason shown first
5. Offline pack downloads in the background; user lands on Home immediately

Principle: ask only what personalises something visible right away.

### 2. Daily open
Home answers "what do I do now?" in one glance: next class and room, what's due, one agent suggestion.

### 3. Study session
Pick course, pick mode (cards / past paper / chat), start in two taps. End screen shows what improved and what to repeat.

### 4. Voting
See poll in Feed, tap an option, confirm, see result state ("Results open after Friday" or live). One vote per person, clearly stated before submitting.

### 5. Filling a form while offline
Fill, submit, see a **Pending** badge and the message "Will send when you're online". On sync, the badge turns to Sent and the user gets a quiet notification.

### 6. Agent action
User: "plan my revision for anatomy." Agent shows a **proposed plan card** with Approve, Edit, Dismiss. Nothing is written until Approve.

## Offline UX rules
- Never show a blank screen: show cached data with "Updated 2 days ago"
- Every write action has a visible queued state
- Features that truly need network (live agent chat) explain why and offer the on-device fallback
- Low-data mode: no images, text only, sync only on Wi-Fi

## Feedback and trust
- Confirm destructive or public actions (posting, voting)
- Undo for 5 seconds where possible
- Plain-language errors, never raw codes
- Show why the agent suggested something ("because your test is in 3 days")

## Accessibility and inclusion
- Swahili and English toggle at any time
- Large-text support, high contrast, screen-reader pass on every release
- Works on low-end Android with small storage: keep the offline pack small and let users clear it

## Research plan (cheap)
- 5 to 8 students per round, 20-minute sessions, on their own phones
- Test: onboarding, finding a room, voting, a study session
- Track: task completion, time on task, confusion points
- Iterate before adding features

## Success metrics
Weekly active students, announcements read rate, poll participation rate, study sessions per week, offline sync success rate, crash-free sessions.
